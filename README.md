# سامانه پرسش و پاسخ مبتنی بر اسناد (LLM RAG Django)

یک سامانه پرسش و پاسخ مبتنی بر اسناد با استفاده از معماری **Retrieval-Augmented Generation (RAG)**، توسعه‌یافته با Django، LangChain و ChromaDB.

این پروژه امکان بارگذاری اسناد، استخراج و پردازش محتوای آن‌ها، جستجوی معنایی و تولید پاسخ با کمک مدل‌های زبانی بزرگ (LLMs) را فراهم می‌کند.

## معرفی پروژه

این پروژه یک سامانه مبتنی بر وب برای پرسش و پاسخ از اسناد متنی است. کاربران می‌توانند اسناد خود را بارگذاری کنند و درباره محتوای آن‌ها سؤال بپرسند.

سیستم با استفاده از معماری **Retrieval-Augmented Generation (RAG)**، ابتدا بخش‌های مرتبط با پرسش کاربر را از میان اسناد بازیابی می‌کند و سپس محتوای بازیابی‌شده را برای تولید پاسخ در اختیار مدل زبانی قرار می‌دهد.

در این رویکرد، پاسخ‌گویی مدل زبانی با اطلاعات بازیابی‌شده از اسناد کاربر ترکیب می‌شود.

## قابلیت‌ها

- بارگذاری، ویرایش و حذف اسناد
- پشتیبانی از فایل‌های DOCX
- استخراج و ذخیره محتوای متنی اسناد
- تقسیم متن اسناد به قطعات کوچک‌تر (Text Chunking)
- جستجوی معنایی با استفاده از ChromaDB
- بازیابی بخش‌های مرتبط با پرسش کاربر
- تولید پاسخ با استفاده از مدل‌های زبانی از طریق OpenRouter
- ذخیره تاریخچه پرسش‌ها و پاسخ‌ها
- مدیریت اسناد و داده‌ها از طریق Django Admin
- ارائه API با Django REST Framework
- پشتیبانی از اجرای پروژه با Docker و Docker Compose

## راه‌اندازی با Docker

### ۱. دریافت کد پروژه

```bash
git clone https://github.com/soroushsalahi/llm-rag-django.git

cd llm-rag-django
```

### ۲. تنظیم متغیرهای محیطی

ابتدا فایل نمونه تنظیمات را کپی کنید:

```bash
cp .env.example .env
```

سپس فایل `.env` را باز کنید:

```bash
nano .env
```

مقادیر موردنیاز را تنظیم کنید:

```env
SECRET_KEY=your-secure-django-secret-key
DEBUG=True
ALLOWED_HOSTS=localhost,127.0.0.1

OPENROUTER_API_KEY=your-openrouter-api-key
OPENROUTER_BASE_URL=https://openrouter.ai/api/v1
LLM_MODEL=openrouter/auto

CHROMA_PERSIST_DIR=./chroma_db
```

مقادیر بالا نمونه هستند. تنظیمات باید با متغیرهای مورد انتظار در کد پروژه مطابقت داشته باشند.

> **نکته امنیتی:** مقدار `SECRET_KEY` باید با یک کلید امن جایگزین شود. فایل `.env` حاوی اطلاعات محرمانه است و نباید در GitHub منتشر شود. مقدار `DEBUG=True` نیز صرفاً برای محیط توسعه مناسب است.

### ۳. اجرای برنامه

```bash
docker-compose up
```

پس از اجرای موفق، برنامه از طریق آدرس زیر در دسترس خواهد بود:

```text
http://localhost:8000
```

برای اجرای برنامه در پس‌زمینه:

```bash
docker-compose up -d
```

برای متوقف کردن سرویس‌ها:

```bash
docker-compose down
```

## راه‌اندازی بدون Docker

### ۱. ساخت محیط مجازی

```bash
python3.11 -m venv venv
```

فعال‌سازی محیط مجازی در Linux و macOS:

```bash
pip install -r requirements.txt
```

### ۳. تنظیم متغیرهای محیطی

```bash
cp .env.example .env
```

سپس مقادیر موردنیاز را مطابق بخش تنظیمات محیطی وارد کنید.

```bash
python manage.py createsuperuser
```

```text
http://127.0.0.1:8000
```

## نحوه استفاده

### پنل مدیریت

پنل مدیریت Django از طریق آدرس زیر قابل دسترسی است:

```text
http://127.0.0.1:8000/admin
```

پس از ورود با حساب مدیر، می‌توانید اطلاعات و داده‌های مدیریتی برنامه را مشاهده و مدیریت کنید.

### بارگذاری سند

برای بارگذاری یک فایل DOCX از API زیر استفاده کنید:

```bash
curl -X POST http://127.0.0.1:8000/api/documents/ \
  -F "title=عنوان سند" \
  -F "file=@/path/to/document.docx"
```

### ارسال پرسش

برای ارسال پرسش درباره اسناد:

```bash
curl -X POST http://127.0.0.1:8000/api/qa/ \
  -H "Content-Type: application/json" \
  -d '{"question_text": "سؤال شما اینجا"}'
```

## مستندات API

این پروژه از Django REST Framework برای ارائه رابط برنامه‌نویسی کاربردی (API) استفاده می‌کند.

### API مدیریت اسناد

| متد HTTP | Endpoint | توضیحات |
|---|---|---|
| GET | `/api/documents/` | دریافت فهرست اسناد |
| POST | `/api/documents/` | بارگذاری سند جدید |
| GET | `/api/documents/{id}/` | دریافت جزئیات سند |
| PUT | `/api/documents/{id}/` | ویرایش سند |
| DELETE | `/api/documents/{id}/` | حذف سند |
| POST | `/api/documents/{id}/reindex/` | ایندکس‌گذاری مجدد سند |

### API پرسش و پاسخ

| متد HTTP | Endpoint | توضیحات |
|---|---|---|
| GET | `/api/qa/` | دریافت تاریخچه پرسش‌ها |
| POST | `/api/qa/` | ارسال پرسش و دریافت پاسخ |
| GET | `/api/qa/{id}/` | دریافت جزئیات یک پرسش |

### نمونه درخواست بارگذاری سند

```bash
curl -X POST http://127.0.0.1:8000/api/documents/ \
  -F "title=هوش مصنوعی" \
  -F "file=@ai_document.docx"
```

### نمونه پاسخ API برای اسناد

نمونه زیر صرفاً برای نمایش ساختار احتمالی پاسخ است:

```json
{
  "id": 1,
  "title": "هوش مصنوعی",
  "file": "http://127.0.0.1:8000/media/documents/ai_document.docx",
  "content": "متن کامل سند...",
  "is_indexed": true,
  "created_at": "2026-05-23T10:00:00+03:30",
  "updated_at": "2026-05-23T10:00:00+03:30"
}
```

### نمونه درخواست پرسش

```bash
curl -X POST http://127.0.0.1:8000/api/qa/ \
  -H "Content-Type: application/json" \
  -d '{"question_text": "هوش مصنوعی چیست؟"}'
```

### نمونه پاسخ پرسش و پاسخ

```json
{
  "id": 1,
  "question_text": "هوش مصنوعی چیست؟",
  "answer_text": "هوش مصنوعی هوشی است که توسط ماشین‌ها استفاده می‌شود...",
  "sources": [
    {
      "document_title": "هوش مصنوعی",
      "relevant_chunk": "بخش مرتبط از سند..."
    }
  ],
  "created_at": "2026-05-23T10:05:00+03:30"
}
```

## معماری و گردش کار RAG

سامانه از رویکرد Retrieval-Augmented Generation برای پاسخ‌گویی مبتنی بر محتوای اسناد استفاده می‌کند.

گردش کار کلی سیستم شامل مراحل زیر است:

### ۱. استخراج متن (Text Extraction)

کاربر یک فایل DOCX بارگذاری می‌کند. محتوای متنی سند با استفاده از ابزار پردازش اسناد استخراج می‌شود.

### ۲. تقسیم‌بندی متن (Text Chunking)

متن استخراج‌شده به قطعات کوچک‌تر (Chunks) تقسیم می‌شود تا امکان پردازش و بازیابی بخش‌های مرتبط فراهم شود.

طبق تنظیمات مستندشده پروژه، اندازه قطعات ۱۰۰۰ کاراکتر و میزان هم‌پوشانی آن‌ها ۲۰۰ کاراکتر است.

### ۳. ایجاد و ذخیره Embeddings

قطعات متنی برای نمایش معنایی به بردارهای عددی (Embeddings) تبدیل می‌شوند. این بردارها همراه با اطلاعات مرتبط در ChromaDB ذخیره می‌شوند.

### ۴. بازیابی اطلاعات (Retrieval)

هنگامی که کاربر پرسشی ارسال می‌کند، سیستم بخش‌های مرتبط با پرسش را از پایگاه داده برداری بازیابی می‌کند.

### ۵. تولید پاسخ (Generation)

بخش‌های بازیابی‌شده به همراه پرسش کاربر در اختیار مدل زبانی قرار می‌گیرند تا پاسخ مبتنی بر محتوای اسناد تولید شود.

## محدودیت‌ها

- در حال حاضر، پردازش اسناد به فایل‌های DOCX محدود است.
- کیفیت پاسخ‌ها به کیفیت محتوای اسناد بازیابی‌شده و مدل زبانی انتخاب‌شده وابسته است.

## پیشنهادهایی برای توسعه آینده

برخی از مسیرهای پیشنهادی برای توسعه و بهبود پروژه عبارت‌اند از:

- توسعه رابط کاربری برای تعامل آسان‌تر با اسناد
